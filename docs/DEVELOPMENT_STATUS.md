# Development Status

Honest picture of what exists, what was checked, and what is still open. Version 1.0.

## Built

- Two-role system (Super Admin, Client admin, Client viewer) with strict per-company data isolation.
- Super Admin: platform overview, create and edit companies, plans, suspend or enable, create and disable logins, reset passwords, "Open" any company as its client view.
- Client app: dashboard (KPIs, daily calls chart, outcomes, sentiment, pipeline, busiest agents), agents (create, edit, delete, activate), Voice Studio (live browser call), calls (search, filters, transcript, summary, captured details), records (leads, appointments, tickets, enquiries, with status workflow), knowledge base, plan and usage meter.
- Five industry packs, each complete in English, Hindi and Gujarati: real estate, healthcare, education, sales, support.
- Voice pipeline with adapters: LLM (mock, Gemini), STT (browser, Sarvam, mock), TTS (browser, Sarvam, mock). Automatic fallback to the mock agent if a provider fails.
- Safety rules in code: emergency words and "speak to a manager" hand off to a human in all three languages.
- Free demo data: three companies with about 120 simulated calls generated by the real agent code.
- Windows one-click setup and run scripts, a beginner guide, tests.

## Not checked (needs your attention)

The environment where this was built had **no internet and no browser**, so these were written carefully but **never executed**:

1. **Starting the real FastAPI server and the WebSocket.** The code follows standard FastAPI patterns, but the first run on your laptop is its first real run. If `run.bat` shows an error, copy it into an AI assistant along with docs/CONTINUE_WITH_AI.md. Then run `scripts/smoke_test.py` to verify.
2. **The web interface in a real browser.** Layout, animations, dark mode and the Voice Studio microphone flow have not been seen on a screen. Expect small visual polish items.
3. **Gemini and Sarvam calls.** Written from current public docs. Possible differences: the Gemini model name (set `GEMINI_MODEL`), the audio format Sarvam accepts from `MediaRecorder` (webm is used; if Sarvam refuses it, convert to wav in the browser), and the list of Sarvam voice names in `config.py`.
4. **Hindi and Gujarati wording.** Written with care, but have a native speaker review `backend/app/packs/*.json` before real customers hear them.

## Known limitations

- Browser calls only. No phone number or telephony provider yet.
- Call audio is not stored (transcripts are). The call drawer says so.
- The caller cannot interrupt the agent by talking over it (they can tap the orb to cut the agent off).
- The mock agent is rule-based: it follows the pack's questions in order and answers knowledge-base questions by keyword matching. It is for demos and offline testing, not for production conversations.
- Sentiment and lead score are simple rules (documented in `services/session.py`, `services/scoring.py`), not AI judgements.
- Gemini replies are capped at 600 tokens of JSON, and the knowledge base is cut to 3,000 characters in the prompt, so keep entries short.
- SQLite and in-memory counters assume **one** server process.
- No email password reset, no audit log, no two-factor login, no export to CSV.
- Plans and prices are placeholders.
- "Reset password" in the admin screen uses a browser prompt box.

## Quality notes for developers

- Backend dependencies are deliberately few: `fastapi`, `uvicorn`, `websockets`, `httpx`. Hashing and tokens use the standard library.
- Frontend has no build step. Files are ES modules served as-is. `html` template literals escape every value by default.
- When changing queries in `routers/client.py`, keep `company_id = ?` in every statement, and run `python -m unittest discover -s tests` plus `scripts/smoke_test.py`.
